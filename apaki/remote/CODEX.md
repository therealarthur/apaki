in their own tab, open Codex or Claude sessions as panes in any tab and in
folders, and make a Codex pane match OpenAI's Codex app as close to 1:1 as
possible: "the model picker, effort picker, bypass session (full access for
codex), voice, attach, etc - all must be usable and properly functional",
"its version of askuserquestiontool - we need to display it similarly", and
"make sure codex/chatgpt sessions have the same knowledge of opening a
browser/viewer in myrlin apaki as it does in codex/chatgpt app".

## Source of truth

The Codex app-server protocol, the one OpenAI's Codex app and IDE extensions
speak (JSON-RPC over stdio, `codex app-server`). Its schema is generated by
the installed CLI: `codex app-server generate-json-schema --out <dir>`
(codex-cli 0.161.0 on 2026-10-11: 104 client requests, 84 server
notifications, 10 server requests). apaki/parity/ keeps snapshots of it and
diffs new versions (PARITY.md). Never write ~/.codex/config.toml: every
setting goes per process (`-c key=value`) or per thread (thread/start
params).

## How it runs

One app-server process per Apaki engine (or per account when Glass needs
separate auths), started with `codex app-server` and per process `-c`
overrides; Apaki is a client like the Codex app. The engine maps app-server
threads, turns and items to the window's existing pane events where they
match, and adds Codex-only events where they do not. Tests drive a fake
app-server that replays recorded JSON-RPC traffic, plus one live smoke test
on this PC that sends nothing billable.
