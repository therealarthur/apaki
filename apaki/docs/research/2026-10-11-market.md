# Myrlin Apaki: market, terms and positioning research

Written 2026-10-11 by Claude Code (Sonnet 5.5) for Arthur. Every URL below was opened on 2026-10-11 unless a line says otherwise. Items I could not verify are tagged UNVERIFIED. This is research, not legal advice.

Access limits that shape the evidence: Reddit blocks direct requests (HTTP 403), so Reddit evidence is limited to one thread read through a public mirror plus search snippets. X was not reachable, so no X claims are made. OpenAI's brand page, help center article 20001542 and service terms returned 403. Mobbin needs a paid login and was skipped, as the brief allowed. GitHub counts are live thumbs-up counts on open issues as of today, pulled with the GitHub API.

## Executive summary

1. The loudest complaint everywhere is usage limits and quota opacity. In anthropics/claude-code, #16157 has 695 thumbs-up and 1,499 comments, #38335 has 476 and 877. The r/ClaudeAI megathread has 803 upvotes and about 6.3k comments. Apaki cannot change limits, but Glass (usage left, switching) and a future auto-continue after reset address the coping behaviour.
2. Multi-account switching is the most-requested desktop feature: Claude Desktop #18435 (881), Claude mobile #36151 (754), Codex #4432 (130), #20500 (115), #12029 (67). Glass is exactly this. It is Apaki's sharpest differentiator and also its largest terms exposure (section 5).
3. Desktop-app reliability on Windows is the second pain: always-on-top window (#85891, 287), a 10 GB Cowork VM (#22543, 231), orphaned-process relaunch failures (#42776, 203 comments), seven reports of Code-tab session history lost on restart, Codex app device-wide lag in August, and a Codex/ChatGPT app that bundles a 1.7 GB runtime. A light Tauri app that rebuilds its list from the transcripts on disk answers these directly, but only if Apaki publishes measured memory and idle CPU numbers.
4. First-party products now cover most of "multi-session desktop" and "phone remote": Claude Desktop's Code tab (sidebar, split panes, browser, terminal, diff, side chat, notifications, SSH, WSL), Claude Remote Control plus the Claude mobile Code tab, and Codex remote from the ChatGPT phone app with a Windows host. Apaki must win on what they do not do: one list of every local session, many accounts in one place, API-key sessions from the phone, Claude and Codex together, Windows-first, open source, and a relay that cannot read content.
5. The closest competitor is Happy (MIT, 24.1k stars, desktop app plus iOS and Android for Claude Code, Codex and Grok, end-to-end encrypted, Windows installer, three releases on 2026-10-11 alone, $19.99 per month Plus in-app purchase). Conductor and Superset moved to iPhone and cloud in 2026 and charge $50 and $20 per user per month. Omnara pivoted away from the phone-first product to a managed-agent platform.
6. Gap list, top priorities: OS notifications and phone push, rewind and checkpoints, a consolidated diff review pane, Codex sessions (planned), git worktree per session, run-in-tray so phone access survives closing the window, auto-continue after a limit resets, and a shortcut cheat sheet. Apaki already has image paste, model and effort and permission pickers, queue and steer, voice, search by meaning, and crash-proof workspace restore.
7. Monetization: sell convenience, not features. Free QR pairing and a fully featured self-hosted relay; Apaki Cloud at about $6 per month or $60 per year with a 30 day no-card trial. Anchors: Home Assistant Cloud $6.50 or $65 (older price, see section 4), Raycast Pro $8 (annual), Tailscale Standard $8 per user, Termius Pro $10. The relay README estimates about $3 per month of overage for twenty heavy users, so margin is not the constraint.
8. License: Apache-2.0 for clients and engine, and AGPL-3.0 for the relay and account service if a competing hosted clone is the worry. Avoid FSL and Elastic License 2.0 (source-available, not OSI open source). Cal.com moved its production code to a private repo in April 2026 and kept an MIT community edition, a live example of how an open-core promise can reverse.
9. Terms: Anthropic allows an end user to sign in to the unmodified Claude Code binary with their own subscription, and its help center said on 2026-10-07 that Agent SDK and third-party apps still draw subscription limits. It does not allow developers to offer claude.ai login, route requests through Free, Pro or Max credentials for users, or collect, store or intermediate claude.ai credentials or session tokens. This policy changed repeatedly in 2026. OpenAI says app-server authentication "has never been permitted for commercial or hosted services"; local and open-source apps may continue. The paid Cloud must never touch Claude or Codex credentials, and Glass needs a written check.
10. Best 2026 dev-tool sites show real product in a framed window. Tenzen Studio's pattern: muted, playsInline H.264 MP4 (1.6 to 6.0 MB), AVIF poster, no autoplay attribute, source attached only when the clip nears the viewport and played at 40 percent visibility. Happy shows two time-synced 64 second videos, a desktop and an iPhone frame, 5.8 MB each. Cursor, Zed and Conductor render the UI as live HTML instead of video. Linear, Raycast and Warp use stills or canvas. Apaki's UI is already HTML, so a scripted live replica is cheap.

### 3.3 Where Apaki is different

- Windows-first: Conductor, Superset, Sculptor and VibeTunnel are Mac or Linux. Happy, Emdash and Nimbalyst list Windows.
- One list of every local Claude Code session including terminal and headless ones, searchable by meaning. Claude Desktop's sidebar shows its own sessions; CLI sessions come in through `/resume` in its prompt box.
- Multi-account in one place (Glass) and per-conversation API billing; I found no listed competitor advertising either.
- API-key sessions from the phone (Remote Control refuses API keys).
- Relay that cannot read content. Be precise in marketing: the model provider sees prompts anyway, so E2E protects against the relay operator, not against Anthropic or OpenAI. Apaki's own SECURITY.md admits the phone page comes from apaki.myrlin.io and that a paired phone can run commands without approval on the PC; I did not find a comparable disclosure in the Happy docs I read (encryption.md, deployment.md).
- Open source plus a self-hostable relay.

### 4.2 Recommendation

- Free forever: the desktop app, the engine, QR phone pairing on the shared relay, and a self-hosted relay with every feature (accounts, any-browser access, Cloud button, push). This keeps the self-host promise in CLOUD.md.
- Apaki Cloud (hosted): $6 per month or $60 per year, 30 day trial with no card (Plausible and Home Assistant both use trials of about a month). Includes passkey account and vault, any-browser sign-in with auto sign-out, the desktop Cloud button listing machines, push notifications, and up to 5 machines. A later Team tier near $8 per user per month (Tailscale Standard) only if shared fleets show up; do not build it now.
- Why this number: it sits between Home Assistant Cloud ($6.50) and Raycast Pro ($8 annual), under Termius ($10), far under agent-tool prices ($20 to $50) that bundle compute. Claude and Codex users already pay $20 to $200 per month for models, so a $5 to $8 add-on is small. The relay README estimates one heavy day at about 14k Durable Object requests and 900 GB-s, inside the plan, and about $3 per month over for twenty such people (relay/README.md, Cost section), so a $6 price has a very high gross margin; price is a signal and a funding mechanism, not a cost recovery.
- Self-hosters and push: Apple only lets the app publisher send APNs pushes. Follow ntfy and Nextcloud: offer a push gateway that self-hosted relays can use for content-free or encrypted wake-up messages, free at low volume. That keeps "self-host fully featured" true without giving away the hosted account service.
- Cheap additions that fit the ecosystem: GitHub Sponsors or Polar donations (VibeTunnel uses Polar), and no bundled model credits. Anthropic bars resale and intermediation of Claude usage (section 5).
- App stores: if the phone app is a native Capacitor build and sells the subscription, Apple's in-app purchase rules apply. In the US, linking to a web checkout is currently allowed and Apple has not been charging commission on it, but the commission question is open before Judge Gonzalez Rogers and a Supreme Court petition is pending (summary of search results: https://www.courthousenews.com/apples-fight-over-commissions-for-linked-out-app-store-purchases-continues-in-district-court/). Guideline 3.1.3(b) on multiplatform services and non-US storefronts were not verified. Happy uses in-app purchase.

### 4.3 License options

| License | What it means for a hosted business |
|-|-|
| MIT | Anyone can host a clone or fork and sell it, no obligation to share changes. Happy and Cal.diy use it. Your moat is the brand, the domain, the published app identity and trust, not the code. |
| Apache-2.0 | Same freedoms plus an explicit patent grant and a termination clause; trademarks are not licensed. Supabase and Omnara use it. Best default for client and engine code. |
| AGPL-3.0 | Anyone running a modified version as a network service must publish their changes. Deters a competitor from taking the relay and accounts code closed, and enables a paid commercial license for those who cannot comply. Cost: some companies ban AGPL, and contributors may hesitate. Plausible, CloudCLI, opcode, claude-squad use it. Good fit for relay and account service only. |
| FSL-1.1 (fair source) | Source is readable and usable except for undermining the producer; each version converts to Apache-2.0 or MIT after two years. Not OSI open source, which breaks "open source" branding. Sentry uses FSL-1.1-Apache-2.0. https://fsl.software/ |
| Elastic License 2.0 | Bars providing the software "to third parties as a hosted or managed service". Not open source. Superset uses ELv2. https://www.elastic.co/licensing/elastic-license |

Recommendation: Apache-2.0 for the desktop app, engine, mobile and web clients; AGPL-3.0 for `relay/` and the account service, with the hosted deployment as the convenient option. The cost of this split is a repository with two licenses, as Bitwarden has. Do not go source-available; the product's trust story depends on reproducible builds and audits by anyone. Cal.com's April 2026 reversal (cited reason: AI tools that scan public code for vulnerabilities, per a third-party summary at https://whyops.com/blog/cal-com-closed-source, UNVERIFIED) is the risk to plan for: keep the commercial layer (billing, entitlement) small and separate so closing it never means closing the product.

### 5.2 OpenAI

- App-server docs: app-server is for deep integration in your own product; ChatGPT login modes are `chatgpt` (Codex owns the OAuth flow) and experimental `chatgptAuthTokens` for host apps that already own the user's ChatGPT auth. "App-server authentication has never been permitted for commercial or hosted services." Existing local or open-source apps "can continue", but OpenAI recommends migrating to Sign in with ChatGPT. The WebSocket transport is "experimental and aren't supported for production workloads", and non-loopback listeners "currently allow unauthenticated connections by default during rollout". Enterprise integrations should contact OpenAI to be added to a known clients list. https://learn.chatgpt.com/docs/app-server (read to character 140,000; redirected from developers.openai.com/codex/app-server)
- Auth docs: `~/.codex/auth.json` is "a plaintext file" to be treated "like a password"; API keys for CI; "Don't expose Codex execution in untrusted or public environments"; Codex cloud requires ChatGPT sign-in. https://learn.chatgpt.com/docs/auth
- Sign in with ChatGPT (plan usage in other apps): "At launch, ChatGPT plan usage is available to open-source projects, personal projects that run locally, and selected private apps." A "paid or remotely hosted app" should "join the waitlist" and "request access before offering it to users"; identity-only access is for selected commercial partners. Plus and Pro users only; users can cap usage per app. https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt and https://developers.openai.com/siwc/quickstart
- Fit for Apaki: a local, open-source desktop app driving Codex on the user's PC is in the allowed bucket today. A paid hosted service is where "commercial or hosted" language bites. The relay does not call OpenAI with user tokens, so the argument is that Cloud is a transport, not an app-server auth consumer; that is my reading, UNVERIFIED, and should be confirmed in writing with OpenAI. Do not run app-server on a network listener; keep it on stdio or loopback behind Apaki's own encrypted channel.
- Trademark: openai.com/brand returned 403. A search summary says the guidelines cover the OpenAI name, logo, ChatGPT and GPT and do not name Codex (UNVERIFIED). Use "for Codex" in plain text, no logos, and a not-affiliated line.

Hero motion: not scroll-driven. After the images decode, a requestAnimationFrame loop runs 5 seconds with the easing t minus sin(2 pi t) over 2 pi, cross-fading through six stills that match the listed steps (Raw, Temp +12, Exposure +0.40, Point Curve, Color Grading, Masking Sky); `prefers-reduced-motion` jumps straight to the last frame.

Demo video embedding (read from the chunk that renders it):

- Element: a plain `<video>` inside a `.window` frame: radius variable of 12px (9.6px inline at the 0.5 scale), rim shadow, optional macOS traffic-light dots, black `#0a0a0b` backing, `.window-media` with `aspect-ratio: 1684 / 1052`.
- Attributes: `muted`, `playsInline`, `preload="none"`, width 1684, height 1052, aria-label describing the clip, `aria-hidden` on clips that are not current. No `autoplay`, no `<source>` children, no `controls`. Most gallery clips have `loop`; the reel clips do not and advance on `timeupdate` near the end.
- Loading: `src="/assets/videos/<name>.mp4"` is attached only after an IntersectionObserver with `rootMargin: 60% 0px` fires; `poster="/assets/videos/<name>.avif"` is always set. The first clip in a reel uses `preload="auto"`.
- Playback: a second observer with thresholds 0, .2, .4, .6, 1 plays at 40 percent visibility and pauses when the tab is hidden or the clip leaves. `prefers-reduced-motion` is detected and switches the clip to its paused state.
- Format: H.264 (avc1) MP4, no audio track in the six I downloaded. Sizes: light_library 3.64 MB, light_develop 5.51 MB, photon_hero 4.78 MB, photon_agent 0.32 MB, capture_demo 6.00 MB, vector_hero 1.63 MB. AVIF posters 64 to 443 KB. `Cache-Control: max-age=14400`.
- Counts per page: /light 5 videos (a reel), / 4, /photon 17 (6-clip reel plus 11-clip gallery), /vector 9, /capture 6, /spectrum 0 (stills only).
- Controls: a 38px round pause and play button in the bottom-right of the frame, blurred background (12px), fades in on hover and focus; reels get progress dots (7px circles; the current one widens to 30px and fills as the clip plays); crossfade between clips .5s.
- Reveal motion: `[data-reveal]` blocks start 28px low and transparent and settle over 1s opacity and 1.2s transform with an ease-out curve when they enter (observer `rootMargin: 0 0 -8% 0`, threshold .12), once, with an optional per-element delay; headings use a text-gradient "sweep" highlight over 1.6s.
- Agent demo: `photon_agent.mp4` ("An AI agent editing a Photon document: the wallpaper turns violet and the title changes", the home page says Codex does it) is only 0.32 MB. A short agent-driving clip is cheap.

Sibling pages share one template; they differ in which clips fill the reel and the gallery. /spectrum has no video.

### 6.3 Takeaways for Apaki's site

1. Show desktop and phone together. Happy's synced pair is the nearest proof that this layout works; Conductor and Superset lead with the phone in 2026.
2. Use real footage as short, muted, `playsInline` H.264 MP4 loops under 6 MB, AVIF or WebP poster, `preload="none"`, attach `src` at about 60 percent root margin, play at 40 percent visible, pause when hidden, honor reduced motion and saveData, and add a visible pause button. One hero reel plus per-feature loops (Tenzen) beats one 64 second film (Happy) for weight and accessibility.
3. Consider a live HTML replica instead of video, as Cursor, Zed and Conductor do. Apaki's UI is already HTML and CSS (apaki/ui), so a scripted conversation on the same stylesheet costs little, stays sharp at any pixel ratio and keeps text selectable. Risk: drift from the real app; mitigate with a build step that renders from the same components.
4. Put an OS-aware primary download button in the hero ("Download for Windows"), as Raycast, Cursor and Happy do, with WinGet as a secondary line.
5. Reveal blocks with a 28 px rise over about 1 s, once, and keep a short agent demo (a few hundred KB) as the proof clip.
6. Lead with the one claim the competitors cannot make: every session on this PC in one window, any account, from your phone, with a relay that cannot read it.
